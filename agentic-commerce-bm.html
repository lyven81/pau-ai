Apa Ia Buat

Typed Contracts. Bukan Screenshot.

Storefront Agentic Commerce expose actions bisnes awak — checkAvailability, getCatalog, createReservation, getQuote — sebagai typed WebMCP tools. AI agent panggil tools ni terus dengan structured arguments dan dapat structured response. Tiada interpretasi screenshot, tiada chat fuzzy, tiada prompt fragile.

Kita build storefront, design typed tools yang match dengan business logic awak, dan handover ia jalan kat domain awak. Chrome 146+, Claude Desktop, dan agentic browser yang muncul boleh transact kat ia.

Soalan Biasa Sebelum Commit

WebMCP tu standard W3C (rolling out Chrome 146+) yang let AI agent call typed tools kat website — macam version webpage of an API. Tanpa ia, AI agent kena baca screenshot dan pura-pura click buttons, yang slow, fragile, dan error-prone.

Awak perlu ia sebab consumer AI agent dah start letak real order on behalf of users. Kalau bisnes awak tak agent-callable, awak invisible kat traffic tu.

Ya. Storefront WebMCP adalah page browser biasa dengan layer agent-callable yang hidden. Human nampak full UI awak dan click buttons macam biasa. AI agent baca typed tools metadata dan call ia terus. Both work side by side.

Structured data (schema.org JSON-LD) bagitahu search engine apa page awak tu. WebMCP tools bagi agent buat something — call functions, check live availability, create reservations, get quotes dengan real-time pricing. Ia difference between agent baca pasal menu awak vs agent betul-betul letak order.

Chrome 146+ dah ship WebMCP support. Claude Desktop dan beberapa agentic browser boleh call WebMCP tools sekarang. Mass adoption 2026–2028. Build sekarang means awak discoverable bila wave sampai — bukan tergesa-gesa catch up lepas.

Boleh. Buka demo Sunny Car Accessories link atas. Both fully agent-callable. Guna Chrome 146+ untuk tengok WebMCP layer in action, atau guna Claude Desktop dengan config yang betul. Kita walk awak through dalam discovery call.
